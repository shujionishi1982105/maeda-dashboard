# スマホ対応レイアウト 設計

- 日付: 2026-08-19
- 対象: `app.py`（まえだ耳鼻咽喉科 経営分析ダッシュボード, Streamlit, GitHub: shujionishi1982105/maeda-dashboard, Streamlit Community Cloud上で公開）
- 対象コミット: f9b6d7a（医師別診療実績ページを改善）

## 背景・目的

現在ダッシュボードはPC（wide layout）向けに作られており、スマホで開くと全体的に見づらい（ユーザーヒアリングで「全体的にすべて」との回答）。PC版はそのまま維持しつつ、スマホでも快適に使えるようにする。

PWA化（ホーム画面への追加）は本設計の対象外とし、別スペックとして後日着手する。今回のスマホ対応が完了し、スマホ表示に切り替えた状態のURLをホーム画面に追加すれば、PWA化前でも「アイコンから開くと自動的にスマホ表示になる」状態は実現できる（後述）。

## スコープ

**含む**
- PC表示／スマホ表示を1つの `app.py`・同一URLで切り替えられるようにする
- 分析メニューのナビゲーションをスマホ表示時はプルダウンにする
- 列数の多い月別マトリクス表をスマホ表示時は直近6ヶ月に絞り込み、全期間表示への切替ボタンを設置する
- 画面幅に応じた軽微なCSS調整（フォントサイズ・余白）

**含まない（対象外）**
- PWA化（manifest.json / アプリアイコン / ホーム画面追加対応）→ 別スペック
- JavaScriptによる画面幅の自動検知・自動モード切替
- オフライン対応
- ログイン機能・データ読み込みロジックの変更
- グラフ（Plotly）の表示方式変更（既存の `use_container_width=True` を維持）

## 表示モードの状態管理

- `st.query_params` の `view` キーで管理する。値は `"pc"`（既定）または `"mobile"`
- 起動時、`view` パラメータが存在しなければ `"pc"` として扱う（既存ブックマーク・共有リンクの挙動を変えない）
- ヘッダー直下に新しい行を追加し、`st.radio` の横並び2択（🖥 PC表示 / 📱 スマホ表示）でモードを切り替える。選択時に `st.query_params["view"]` を更新して `st.rerun()` する
- この仕組みにより、スマホ表示に切り替えた状態のURL（`?view=mobile`）でホーム画面に追加すれば、次回以降アイコンから開いても自動的にスマホ表示になる

## UI変更の詳細

### 1. 分析メニューのナビゲーション（`app.py` 289〜314行付近）

現状：`pages` リスト（8項目）を4列×2行のボタングリッドで表示し、`st.session_state.current_page` を更新。

変更：`view == "mobile"` のとき、ボタングリッドの代わりに `st.selectbox("🔍 分析メニュー", pages, index=pages.index(st.session_state.current_page))` を表示し、選択値が変わったら `st.session_state.current_page` を更新して `st.rerun()`。`view == "pc"` のときは現状のボタングリッドのまま。

### 2. 月別マトリクス表の直近6ヶ月表示（対象3箇所）

月が列方向に並ぶワイドな表（横スクロールが辛い表）のみを対象にする。月が行方向の表（レセプト分析・外来収入金額推移分析・年齢別構成比分析など）は列数が少なく対象外。

対象:
1. 診療行為一覧分析 `matrix_full_df`（1198〜1220行付近）
2. 検査一覧分析 `matrix_full_df`（1497〜1519行付近）
3. 医師別診療実績（月別） `matrix_doc_df`（1744〜1766行付近）

共通処理として、月列を絞り込むヘルパー関数を1つ新設する（例: `limit_recent_months(df, month_cols, n=6)`）。`view == "mobile"` のときは既定で直近6ヶ月＋`年間合計`列のみを表示し、表の直前に「📅 全期間を表示」ボタン（`st.session_state`にキーを持たせたトグル）を置き、押すと同じ表を全期間表示に切り替える。`view == "pc"` のときは常に全期間表示（現状のまま）。トグルの状態は3箇所それぞれ独立（表ごとに別の`session_state`キー）で持たせる。1画面には常にどれか1つの分析モードしか表示されないため、他の表の状態と干渉することはない。

### 3. CSS微調整

既存の `st.markdown("""<style>...""")` ブロックに `@media (max-width: 768px)` を追加し、フォントサイズ・見出し余白などスマホでの可読性を上げる。これは実際の画面幅に応じてブラウザが自動適用する純粋なCSSであり、`view` パラメータとは独立して常に効く（PC表示モードのままスマホの狭い画面で見た場合も多少読みやすくなる）。

## 影響を受けないもの

- Plotlyグラフの生成ロジック・`use_container_width=True` の設定
- ログイン処理、CSV読み込み・集計処理
- レセプト分析／外来収入金額推移分析／年齢別構成比分析の表（月が行方向のため対象外）

## テスト・検証方法

このプロジェクトに自動テストは存在しないため、これまで通り手動検証する。
1. `streamlit run app.py` をローカル（WSL、`--break-system-packages` でpandas等インストール済み環境）で起動
2. ブラウザの開発者ツールでスマホ幅（375px程度）と通常のPC幅の両方で全8分析モードを一通り確認
3. `view=mobile` / `view=pc` をURLパラメータで直接指定し、それぞれの初期表示が正しいことを確認
4. 直近6ヶ月表示⇄全期間表示の切り替えボタンが3箇所すべてで正しく動作することを確認
5. 既存のPC表示（`view`パラメータなしでアクセスした場合）が変更前と見た目・挙動とも変わらないことを確認
